# P1-04 - Access model: levels 0-4, read hides, write locks, L4 session

- Phase: 1
- Size: M
- Status: done
- Depends on: P1-01
- Requirement refs: §4.1 access levels; §8.15 L4 time-limited; Excel Access Lvl Read/Write

## Goal
Decide per parameter and per screen what the current level may see and change. Unreadable parameters are not rendered at all; readable but not writable ones show a lock.

## Scope
- src/core/access.js: canRead(param, level), canWrite, canOpen(node, level), grantable levels for user creation
- Level 0 after start and after auto log-off; L4 opened by secure code for N minutes (param 902), closes by itself
- Nodes with accessRead from overrides (§8) gate tiles and routes

## Acceptance criteria
- [ ] L0 has no menu access; the badge shows 0
- [ ] A row with accessRead > level is absent, accessWrite > level shows lock and a "needs level n" toast on tap
- [ ] L4 expires and the badge drops back to the previous level
- [ ] L3 may grant levels 1, 2 and 3 when creating users

## Tests
- tests/unit/access.test.js per level matrix
