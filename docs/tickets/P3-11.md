## Goal
USB file browser, create-backup flow with naming dialog pre-filled with device name + serial + date and the choice Backup or Format; progress and result.

## Scope
- src/ui/screens/service/Backup.js
- Seed USB tree; no-USB empty state

- [x] L2 create, L3 load

## Done (2026-11-10)
- `src/core/backup.js`: the simulated drive (`usb` slice, persisted; seeded once per device with a backups folder holding two backups, a format, a sub-folder from another machine and a foreign PDF, a firmware folder and a readme), file kinds by extension (Backup `.bak` = every editable parameter + the formats; Format `.fmt` = the format-relevant parameters only), default name `<device>_<serial>_<yyyy-mm-dd>` made FAT-safe, snapshots, write / replace, restore diff. `machine.usb` (simulator `setUsb`, dev panel buttons `usb` / `nousb`) says whether a drive is plugged in; the status bar shows a USB icon while it is.
- `src/ui/screens/service/Backup.js` (node `backup`), one flow on one screen:
  - browse: the shared file browser (path bar, one level up, folders, files with size and date, foreign files greyed out), the selection line, "Create backup here" (L2) and "Load" (L3; locked with a toast below). No drive → the "No USB drive" empty state; plugging one in brings the browser back.
  - name: the file name pre-filled (tap to edit with the keyboard; spaces and `\ / : * ? " < > |` refused), the choice Backup / Format as two radio cards with what each holds and is for, Cancel / Save. A name that exists in the folder asks before replacing (destructive).
  - run: progress with phase text and "Do not remove the USB drive until this is finished"; back, menu and user are refused with a toast while it runs (`ctx.busy`). Pulling the drive ends in the failure state with what to do next.
  - result: success (file name, size and folder / number of parameters changed) or failure, then Done.
  - Load asks first (destructive, Backup and Format texts differ), is refused while the machine runs (`whenStopped`, re-checked at the end), changes only parameters that differ, a Backup also restores the formats; a log entry for every write and load.
- Tests: `tests/unit/backup.test.js` (7), `tests/e2e/backup.spec.js` (8 × 2 layouts).
- Figma: four portrait frames on "HMI / 04 Screens – Special" (row y 5760): browse-L3, name-L2, running-L2, nousb-L2. The browse frame was finished by hand (the builder stalls on swapping an icon inside a Button instance).
