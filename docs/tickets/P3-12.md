- Simulator update progress

## Done (2026-11-10)
- `src/core/firmware.js`: firmware files (`*.fw`), version from the entry or the name, numeric comparison, direction (upgrade / downgrade / same), install phases (signature → copy → write → verify). The dummy drive's `firmware` folder: 0.02 (newer), 0.03-rc (signature not valid), release notes (greyed), `archive/` with 0.00 (downgrade) and a damaged copy of 0.02.
- `src/ui/screens/service/FwUpdate.js` (node `fwupdate`, L3):
  - select: the shared file browser, opening on `USB › firmware`, non-firmware files greyed out; the versions card (Installed · since date › Selected · file date) with the step in words ("Newer version", "Older version: a downgrade is allowed" in amber, "Same version as installed"); what happens ("stops the machine, about two minutes, restarts"); one primary "Install". Confirmation names both versions (and says "older version" for a downgrade); refused while the machine runs. Landscape: browser left, the panel (340 px) right.
  - update: its own view titled "Firmware update", no back in the title bar, back / menu / user refused with a toast (`ctx.busy`); phase text and bar; "Do not switch off the machine or remove the USB drive."
  - result: success → "Update successful", the new version, "Restart machine" (still no back) → `ctx.restart()`: session ends, start-up screen, boot, home; the installed version is kept across reloads (`settings.firmware`) and written to parameter 702. Rejected (invalid signature, checked first) and failed (image could not be written, drive removed) keep the installed version and list what to do next, then "Back to files". Long result cards scroll instead of being cut.
- Tests: `tests/unit/firmware.test.js` (5), `tests/e2e/fwupdate.spec.js` (8 × 2 layouts).
- Figma: four portrait frames on "HMI / 04 Screens – Special" (row y 6720): select-L3, running-L3, success-L3, rejected-L3; new TitleBar variant `Back=no, Subtitle=no, Branch=service`.
